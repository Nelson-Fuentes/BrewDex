# Quickstart: Selección de Juego para el Constructor de Equipos

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Data model**: [data-model.md](./data-model.md) | **Contracts**: [contracts/](./contracts/)

This guide validates the feature end-to-end once implemented. It does not
contain implementation code — see `tasks.md` (generated by
`/speckit-tasks`) for that.

## Prerequisites

- Flutter SDK installed (latest stable channel) with Android and Web
  targets enabled — verify with:
  ```bash
  flutter doctor
  ```
- Project dependencies installed:
  ```bash
  flutter pub get
  ```
- Network access to `pokeapi.co` (the game catalog is fetched live — see
  research.md item 6).

## Run the app

Web target:
```bash
flutter run -d chrome
```

Android target (emulator or device attached):
```bash
flutter run -d android
```

## Automated validation

Unit + widget + Cubit tests (domain, application, infrastructure,
presentation):
```bash
flutter test
```

End-to-end flow (on a running device/emulator or headless Chrome):
```bash
flutter test integration_test/game_selection_flow_test.dart
```

## Manual validation scenarios

Each scenario below maps to an acceptance scenario in `spec.md` and
should be checked by hand at least once before considering the feature
done, in addition to the automated tests above.

### 1. First-time selection (User Story 1 / SC-001, SC-002)

1. Launch the app with no prior selection (fresh install, or clear local
   storage for the app).
2. Confirm the full game catalog is shown before any team-building action
   is reachable.
3. Pick a game.
4. Confirm the app reports that game as the active selection and that
   team-building is now reachable.

### 2. Returning with a remembered selection (Acceptance Scenario 1.3 / SC-003)

1. With a game already selected (from scenario 1), close and reopen the
   app.
2. Confirm the previously selected game is shown as the active selection
   without needing to reselect it.

### 3. Interactive search and generation filter (User Story 2 / SC-002)

1. Open the game selector.
2. Type a partial name of a known game and confirm only matching games
   remain visible.
3. Clear the search and instead pick a generation filter; confirm only
   games from that generation remain visible.
4. Search for text that matches no game; confirm a clear "no matches"
   state appears with a way to clear the search/filter.

### 4. Switching games with an in-progress team (User Story 3 / SC-004)

1. Select Game A, then add at least one Pokémon that is *not* available
   in Game B to the in-progress team (requires the future team-building
   feature to be present; otherwise simulate via test fixtures — see
   `test/application/game_selection/switch_game_test.dart`).
2. Switch the active selection to Game B.
3. Confirm the invalid Pokémon is removed and a notice lists what was
   removed and why.
4. Repeat with a team that only contains Pokémon valid in both games and
   confirm the team is left unchanged after switching.

### 5. Catalog unavailable (Edge case / SC-005)

1. Disable network access (e.g. airplane mode, or block `pokeapi.co` in a
   proxy) before opening the game selector.
2. Confirm a clear, actionable error is shown instead of a broken or
   endlessly-loading selector.
3. Re-enable network access and use the provided retry action.
4. Confirm the catalog then loads normally.

## Expected outcome

All five scenarios pass, all automated tests in `flutter test` and
`integration_test/game_selection_flow_test.dart` pass, and no domain or
application source file under `lib/domain/game_selection` or
`lib/application/game_selection` imports Flutter, `http`, or
`shared_preferences` (spot-check with `grep -rl "package:flutter\|package:http\|package:shared_preferences" lib/domain lib/application` — expect no matches).
